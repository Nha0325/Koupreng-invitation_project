# Koupreng Next Feature Roadmap

This roadmap records advanced modules that are missing, partial, or present but still need product/security hardening. It is intentionally scoped as implementation guidance, not a rewrite plan.

| Feature | Current status | Purpose | Backend files needed | Frontend routes needed | Priority | Security notes |
| --- | --- | --- | --- | --- | --- | --- |
| QR check-in | Partial backend present | Let staff scan guest QR codes and mark arrivals at the event. | Harden `CheckInService`, `CheckInController`, `GuestRepository`; add audit log events and check-in permission tests. | `/dashboard/invitations/:invitationId/check-in`, staff scanner view. | High | Require owner/admin/staff authorization; rate-limit scans; avoid exposing full guest lists through QR payloads. |
| Table and seat management | Partial backend present | Assign guests to tables/seats and export seating plans. | Harden `SeatingService`, `GuestSeatAssignmentRepository`, table entities, CSV/PDF export service. | `/dashboard/invitations/:invitationId/seating`, table editor, seat map. | High | Enforce invitation ownership; validate seat counts; prevent cross-invitation table assignment. |
| Subscription/package system | Partial backend present | Sell recurring or package-based platform access beyond one-off templates. | Review `SubscriptionController`, `SubscriptionService`, package entities, payment linking, expiry jobs. | `/dashboard/packages`, `/dashboard/subscriptions`, admin package editor. | Medium | Never unlock packages from frontend callbacks; enforce payment confirmation source; expire access predictably. |
| Payment history and receipt | Partial backend present | Let users/admins inspect payment orders, statuses, and receipts. | Harden `PaymentHistoryController`, `PaymentHistoryService`, receipt rendering/export tests. | `/dashboard/payments`, `/dashboard/payments/:orderCode`, admin payment detail page. | High | Owner/admin checks on every order; mask transaction metadata; immutable receipt records after paid. |
| AI invitation assistant | Partial or experimental | Help hosts draft invitation wording, schedules, and bilingual copy. | Add `AiAssistantController`, service abstraction, prompt templates, usage limits, moderation. | `/dashboard/invitations/:invitationId/assistant`. | Medium | Do not send secrets or private guest data by default; rate-limit usage; log model usage without storing sensitive prompts unnecessarily. |
| Organization/team account | Partial backend present | Allow teams to manage invitations with roles and shared permissions. | Harden `OrganizationController`, `OrganizationService`, member roles, invitation ownership model. | `/dashboard/organizations`, `/dashboard/organizations/:organizationId/members`. | Medium | Enforce role-based access on invitations, budgets, guests, payments, and exports; audit membership changes. |
