Koupreng API Postman Testing Guide
Generated for local testing only.

Base URL:
  {{baseUrl}} = http://<backend-host>:8080

Recommended Postman environment variables:
  baseUrl = http://<backend-host>:8080
  accessToken = paste token from register/login/google/telegram response
  adminToken = paste token for a user with role ADMIN
  adminPaymentSecret = value from local ADMIN_PAYMENT_SECRET env only
  invitationId = set from create invitation response data.id
  invitationSlug = set from create/publish invitation response data.slug
  guestId = set from create guest response data.id
  inviteToken = set from create guest response data.inviteToken
  mediaId = set from upload/list media response data.id or data.all[0].id
  orderCode = set from create PayWay checkout response data.orderCode
  transactionId = set from create PayWay checkout response data.transactionId
  templateId = 10
  googleIdToken = real Google ID token from Google sign-in
  telegramIdToken = real Telegram OIDC ID token, if using Telegram OIDC
  paywaySignature = X-PAYWAY-HMAC-SHA512 header sent by ABA PayWay callback

Common headers:
  Content-Type: application/json
  Authorization: Bearer {{accessToken}}

Admin headers:
  Authorization: Bearer {{adminToken}}

Admin template payment headers:
  Authorization: Bearer {{adminToken}}
  X-ADMIN-PAYMENT-SECRET: {{adminPaymentSecret}}

Response format notes:
  Auth endpoints return AuthResponse directly:
    {
      "accessToken": "...",
      "tokenType": "Bearer",
      "expiresAt": "...",
      "user": { ... }
    }

  Most business endpoints return ApiResponse:
    {
      "success": true,
      "message": "...",
      "data": { ... },
      "timestamp": "..."
    }

Postman Tests tab snippet for register/login/google/telegram:
  const json = pm.response.json();
  pm.environment.set("accessToken", json.accessToken);
  if (json.user && json.user.role === "ADMIN") {
    pm.environment.set("adminToken", json.accessToken);
  }

Postman Tests tab snippet for ApiResponse IDs:
  const json = pm.response.json();
  if (json.data && json.data.id) pm.environment.set("invitationId", json.data.id);
  if (json.data && json.data.slug) pm.environment.set("invitationSlug", json.data.slug);

Important security/testing notes:
  - Do not paste real ABA keys, Telegram bot token, JWT secret, or .env contents into Postman docs.
  - Frontend never marks an order PAID.
  - PayWay return/success pages are UI only.
  - Order becomes PAID only after backend callback verification and backend PayWay transaction verification.
  - PayWay callback should be tested with real ABA sandbox callback data and header.
  - If templates table has rows, payment templateId must exist in templates.template_id. If it is empty, templateId 10 can be used for sandbox testing.
  - There is no backend template catalog listing controller currently. Template gallery data is frontend static; backend stores templateId in invitations and template payment/access records.

Enums:
  Role: USER, ADMIN
  TemplateType: WEDDING, ENGAGEMENT, BIRTHDAY, GRADUATION, CORPORATE, HOUSEWARMING, OPENING

D. Media/File Management
============================================================

Postman multipart setup:
  Body tab -> form-data.
  For file fields choose Type = File.
  For text fields choose Type = Text.

Allowed file types:
  Cover/gallery: jpg, jpeg, png, webp. Max 5MB.
  Video: mp4, webm. Max 50MB.
  Music: mp3, wav, ogg. Max 15MB.
  Executables are rejected.

PowerShell note:
  PowerShell multipart can send files as application/octet-stream.
  In curl use explicit MIME type, for example:
    curl.exe -F "file=@cover.png;type=image/png" ...

E.1 Create PayWay checkout
  Method: POST
  URL: {{baseUrl}}/api/v1/template-payments/payway/create
  Headers:
    Authorization: Bearer {{accessToken}}
  Body:
  {
    "templateId": 10,
    "templateName": "Khmer Wedding Gold",
    "packageName": "Premium",
    "amount": 5.00,
    "currency": "USD",
    "buyerName": "Postman User",
    "buyerEmail": "postman.user@example.com",
    "buyerPhone": "85512345678"
  }
  Expected: 201
  Save:
    data.orderCode -> orderCode
    data.transactionId -> transactionId
  Notes:
    Response data.checkoutUrl is the PayWay purchase endpoint.
    Response data.checkoutFormFields contains backend-generated PayWay form fields.
    Open/submit the checkout form in browser/frontend to continue the sandbox payment.

E.2 Get order status
  Method: GET
  URL: {{baseUrl}}/api/v1/template-payments/{{orderCode}}
  Headers:
    Authorization: Bearer {{accessToken}}
  Expected:
    200 for owner or ADMIN.
    403 for another user.
  Status flow:
    PENDING -> CHECKOUT_CREATED -> PAID/FAILED/CANCELLED/EXPIRED/REJECTED

E.3 PayWay callback - real sandbox callback only
  Method: POST
  URL: {{baseUrl}}/api/v1/payway/callback
  Auth: none
  Headers:
    Content-Type: application/json
    X-PAYWAY-HMAC-SHA512: {{paywaySignature}}
  Body example shape:
  {
    "tran_id": "{{transactionId}}",
    "status": "0",
    "amount": "5.00",
    "currency": "USD",
    "apv": "APPROVED",
    "payment_option": "abapay"
  }
  Expected:
    200 only when the signature/header is valid and backend PayWay transaction verification approves the transaction.
    401 for missing/invalid callback signature.
    400 for amount/currency mismatch after verification.
  Critical:
    Do not use this sample to fake a paid payment. The backend also calls PayWay check-transaction before marking PAID.

E.4 Paid templates after verified payment
  Method: GET
  URL: {{baseUrl}}/api/v1/me/templates/paid
  Headers:
    Authorization: Bearer {{accessToken}}
  Expected:
    200, includes template only after backend marks order PAID.

E.5 Template access after verified payment
  Method: GET
  URL: {{baseUrl}}/api/v1/me/templates/10/access
  Headers:
    Authorization: Bearer {{accessToken}}
  Expected:
    data.hasAccess true only after PAID order unlocks template.

E.6 Admin list template payment orders
  Method: GET
  URL: {{baseUrl}}/api/v1/admin/template-payments
  Headers:
    Authorization: Bearer {{adminToken}}
    X-ADMIN-PAYMENT-SECRET: {{adminPaymentSecret}}
  Expected:
    200 for ADMIN with valid admin payment secret.
    401 if X-ADMIN-PAYMENT-SECRET is missing.
    403 if X-ADMIN-PAYMENT-SECRET is wrong or JWT role is not ADMIN.

E.7 Negative payment tests
  Invalid amount:
    POST {{baseUrl}}/api/v1/template-payments/payway/create
    Body amount = 0
    Expected: 400

  Invalid currency:
    POST {{baseUrl}}/api/v1/template-payments/payway/create
    Body currency = "EUR"
    Expected: 400

  Duplicate purchased template:
    Create checkout after template already unlocked.
    Expected: 409 "Template already unlocked"

  Other user reads order:
    Login as second user, GET /api/v1/template-payments/{{orderCode}}
    Expected: 403

F. Security Layer Tests
============================================================

F.1 Protected endpoint without token
  Method: GET
  URL: {{baseUrl}}/api/v1/invitations/my
  Auth: none
  Expected: 401

F.2 Protected endpoint with invalid token
  Method: GET
  URL: {{baseUrl}}/api/v1/invitations/my
  Headers:
    Authorization: Bearer invalid.token.value
  Expected: 401

F.3 Owner authorization
  Steps:
    1. User A creates invitation and saves invitationId.
    2. User B logs in.
    3. User B calls GET {{baseUrl}}/api/v1/invitations/{{invitationId}}
  Expected: 403

F.4 Admin route with USER token
  Method: GET
  URL: {{baseUrl}}/api/admin/users
  Headers:
    Authorization: Bearer {{accessToken}}
  Expected: 403 unless accessToken belongs to ADMIN.

F.5 Admin template payment route missing secret
  Method: GET
  URL: {{baseUrl}}/api/v1/admin/template-payments
  Headers:
    Authorization: Bearer {{adminToken}}
  Expected: 401

F.6 Admin template payment route wrong secret
  Method: GET
  URL: {{baseUrl}}/api/v1/admin/template-payments
  Headers:
    Authorization: Bearer {{adminToken}}
    X-ADMIN-PAYMENT-SECRET: wrong-secret
  Expected: 403

F.7 WAF path traversal
  Method: GET
  URL: {{baseUrl}}/api/users/../admin
  Auth: none
  Expected:
    Blocked by WAF/security, usually 403 or 400 depending on path normalization.

F.8 WAF SQL injection pattern
  Method: POST
  URL: {{baseUrl}}/api/auth/login
  Auth: none
  Body:
  {
    "identifier": "admin@example.com' OR '1'='1",
    "password": "anything"
  }
  Expected:
    Blocked by WAF with 403, or rejected as bad credentials if pattern is not matched by local config.

F.9 Auth rate limit
  Method: POST
  URL: {{baseUrl}}/api/auth/login
  Auth: none
  Body:
  {
    "identifier": "wrong@example.com",
    "password": "wrong-password"
  }
  Expected:
    After repeated attempts in one minute, 429.
  Default local limit:
    login 10/minute
    register 5/minute
    social login 20/minute

F.10 CORS preflight
  Method: OPTIONS
  URL: {{baseUrl}}/api/v1/invitations/my
  Headers:
    Origin: http://localhost:5173
    Access-Control-Request-Method: GET
    Access-Control-Request-Headers: Authorization, Content-Type
  Expected:
    Allowed if CORS config includes http://localhost:5173.

Suggested End-to-End Postman Flow
============================================================

1. GET /api/health.
2. POST /api/auth/register, save accessToken.
3. GET /api/users/me.
4. POST /api/v1/invitations, save invitationId and invitationSlug.
5. POST /api/v1/invitations/{{invitationId}}/guests, save guestId and inviteToken.
6. POST /api/v1/invitations/{{invitationId}}/media/cover with a real png/jpg file.
7. PATCH /api/v1/invitations/{{invitationId}}/publish, save slug again.
8. GET /api/v1/public/invitations/{{invitationSlug}} without token.
9. POST /api/v1/public/invitations/{{invitationSlug}}/rsvp without token.
10. POST /api/v1/template-payments/payway/create, save orderCode and transactionId.
11. GET /api/v1/template-payments/{{orderCode}}, confirm CHECKOUT_CREATED.
12. Continue payment in ABA PayWay sandbox from frontend/browser.
13. Confirm backend receives /api/v1/payway/callback from ABA.
14. GET /api/v1/template-payments/{{orderCode}}, confirm PAID only after callback/verification.
15. GET /api/v1/me/templates/paid, confirm template appears.
16. GET /api/v1/me/templates/10/access, confirm hasAccess true.
17. Login as another user and confirm they cannot read User A invitation/order.
18. Use admin token and admin payment secret to test admin listing.
