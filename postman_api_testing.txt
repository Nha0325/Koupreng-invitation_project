# Koupreng Invitation Project - Backend APIs for Postman

Base URL:
http://localhost:8080

Recommended Postman environment variable:
- baseUrl = http://localhost:8080

Default JSON header for requests with a body:
- Key: Content-Type
- Value: application/json

Authentication for protected APIs:
- Key: Authorization
- Value: Bearer <accessToken>

Get <accessToken> from the response body of register, login, Google login, or Telegram login.
If AUTH_COOKIE_ENABLED=true, Postman can use the saved koupreng_access_token cookie instead.
Authorization bearer headers still work and take priority over the cookie.

================================================================================
1. Public Endpoints - No Authentication Required
================================================================================

Health Check - Root
- Method: GET
- URL: {{baseUrl}}/
- Body: None

Health Check - API
- Method: GET
- URL: {{baseUrl}}/api/health
- Body: None

Register a New User
- Method: POST
- URL: {{baseUrl}}/api/auth/register
- Body (JSON):
{
  "fullName": "John Doe",
  "email": "john@example.com",
  "phone": "+85512345678",
  "password": "SecurePassword123!"
}
- Notes:
  - fullName and password are required.
  - At least one of email or phone is required.
  - Accepted aliases for fullName: fullname, full_name.
  - Response includes accessToken, tokenType, expiresAt, and user.

Login
- Method: POST
- URL: {{baseUrl}}/api/auth/login
- Body (JSON):
{
  "identifier": "john@example.com",
  "password": "SecurePassword123!"
}
- Notes:
  - identifier can be email or phone.
  - Accepted aliases for identifier: email, phone, emailOrPhone.
  - Response includes accessToken, tokenType, expiresAt, and user.

Google Login
- Method: POST
- URL: {{baseUrl}}/api/auth/google
- Body (JSON):
{
  "idToken": "<google_id_token>"
}
- Notes:
  - Requires a valid Google ID token configured for this backend.
  - Response includes accessToken, tokenType, expiresAt, and user.

Telegram Login
- Method: POST
- URL: {{baseUrl}}/api/auth/telegram
- Body (JSON):
{
  "idToken": "<optional_telegram_oauth_token>",
  "id": 123456789,
  "first_name": "John",
  "last_name": "Doe",
  "username": "johndoe",
  "photo_url": "https://t.me/i/userpic/320/johndoe.jpg",
  "auth_date": 1716500000,
  "hash": "<telegram_hash>"
}
- Notes:
  - idToken is optional when using Telegram widget fields.
  - Accepted aliases: firstName, lastName, photoUrl, authDate.
  - Response includes accessToken, tokenType, expiresAt, and user.


================================================================================
2. Authenticated User Endpoints - Require Login
================================================================================

Get Current User Profile
- Method: GET
- URL: {{baseUrl}}/api/users/me
- Auth: Bearer <accessToken> or koupreng_access_token cookie
- Body: None

Update Current User Profile
- Method: PATCH
- URL: {{baseUrl}}/api/users/me
- Auth: Bearer <accessToken> or koupreng_access_token cookie
- Body (JSON):
{
  "fullName": "Johnathan Doe"
}

Logout
- Method: POST
- URL: {{baseUrl}}/api/auth/logout
- Auth: Bearer <accessToken> or koupreng_access_token cookie
- Body: None
- Notes:
  - Logout increments token_version, so old JWTs stop working.
  - If cookie mode is enabled, logout also clears the auth cookie.


================================================================================
3. Admin Endpoints - Require ADMIN Role
================================================================================

These endpoints require an authenticated user with ADMIN role.
Use Authorization: Bearer <admin_accessToken> or the saved admin auth cookie.

List All Users
- Method: GET
- URL: {{baseUrl}}/api/admin/users
- Auth: ADMIN
- Body: None

Update a User's Role
- Method: PATCH
- URL: {{baseUrl}}/api/admin/users/{userId}/role
- Example URL: {{baseUrl}}/api/admin/users/1/role
- Auth: ADMIN
- Body (JSON):
{
  "role": "ADMIN"
}
- Valid role values:
  - USER
  - ADMIN


================================================================================
4. Event Endpoints - Require Login
================================================================================

Event APIs are authenticated because /api/v1/events/** is not in the public
permit list. Use Authorization: Bearer <accessToken> or the saved auth cookie.

Valid templateType values:
- WEDDING
- ENGAGEMENT
- BIRTHDAY
- GRADUATION
- CORPORATE
- HOUSEWARMING
- OPENING

Event status values returned by the API:
- DRAFT
- PUBLISHED
- UNPUBLISHED

Event Request JSON for Create and Update
{
  "eventName": "John & Jane Wedding",
  "templateType": "WEDDING",
  "groom": "John",
  "bride": "Jane",
  "eventDate": "2026-06-15",
  "eatingTime": "18:30:00",
  "location": "Phnom Penh",
  "description": "Wedding invitation event",
  "coverImageUrl": "https://example.com/cover.jpg"
}

Required event fields:
- eventName
- templateType
- eventDate

Create Event
- Method: POST
- URL: {{baseUrl}}/api/v1/events
- Auth: Bearer <accessToken> or koupreng_access_token cookie
- Body: Event Request JSON
- Notes:
  - New events always start with status DRAFT.

List All Events
- Method: GET
- URL: {{baseUrl}}/api/v1/events
- Auth: Bearer <accessToken> or koupreng_access_token cookie
- Body: None

List Published Events
- Method: GET
- URL: {{baseUrl}}/api/v1/events/published
- Auth: Bearer <accessToken> or koupreng_access_token cookie
- Body: None

List Draft Events
- Method: GET
- URL: {{baseUrl}}/api/v1/events/drafts
- Auth: Bearer <accessToken> or koupreng_access_token cookie
- Body: None

Get Event by ID
- Method: GET
- URL: {{baseUrl}}/api/v1/events/{id}
- Example URL: {{baseUrl}}/api/v1/events/1
- Auth: Bearer <accessToken> or koupreng_access_token cookie
- Body: None

Preview Event
- Method: GET
- URL: {{baseUrl}}/api/v1/events/{id}/preview
- Example URL: {{baseUrl}}/api/v1/events/1/preview
- Auth: Bearer <accessToken> or koupreng_access_token cookie
- Body: None

Update Event - New Update API
- Method: PUT
- URL: {{baseUrl}}/api/v1/events/{id}
- Example URL: {{baseUrl}}/api/v1/events/1
- Auth: Bearer <accessToken> or koupreng_access_token cookie
- Body: Event Request JSON
- Notes:
  - coverImageUrl is updated only when it is included and not null.

Save Event as Draft
- Method: PATCH
- URL: {{baseUrl}}/api/v1/events/{id}/draft
- Example URL: {{baseUrl}}/api/v1/events/1/draft
- Auth: Bearer <accessToken> or koupreng_access_token cookie
- Body: None

Publish Event
- Method: PATCH
- URL: {{baseUrl}}/api/v1/events/{id}/publish
- Example URL: {{baseUrl}}/api/v1/events/1/publish
- Auth: Bearer <accessToken> or koupreng_access_token cookie
- Body: None
- Notes:
  - Returns an error if the event is already published.

Unpublish Event
- Method: PATCH
- URL: {{baseUrl}}/api/v1/events/{id}/unpublish
- Example URL: {{baseUrl}}/api/v1/events/1/unpublish
- Auth: Bearer <accessToken> or koupreng_access_token cookie
- Body: None
- Notes:
  - Returns an error if the event is not currently published.

Delete Event - Soft Delete
- Method: DELETE
- URL: {{baseUrl}}/api/v1/events/{id}
- Example URL: {{baseUrl}}/api/v1/events/1
- Auth: Bearer <accessToken> or koupreng_access_token cookie
- Body: None
- Notes:
  - This is a soft delete.

6. Suggested Postman Smoke Test Flow
================================================================================

1. GET {{baseUrl}}/api/health
2. POST {{baseUrl}}/api/auth/register
3. Save accessToken from the response.
4. GET {{baseUrl}}/api/users/me with Authorization: Bearer <accessToken>
5. POST {{baseUrl}}/api/v1/events with Event Request JSON.
6. Save event id from response.data.id.
7. PUT {{baseUrl}}/api/v1/events/{id} with updated Event Request JSON.
8. PATCH {{baseUrl}}/api/v1/events/{id}/publish
9. GET {{baseUrl}}/api/v1/events/published
10. PATCH {{baseUrl}}/api/v1/events/{id}/unpublish
11. PATCH {{baseUrl}}/api/v1/events/{id}/draft
12. DELETE {{baseUrl}}/api/v1/events/{id}
13. Use an ADMIN token only for GET {{baseUrl}}/api/admin/users and role updates.

Do not test frontend placeholder routes like /weddings or /guests as backend
routes. No backend controller currently exposes those endpoints.
